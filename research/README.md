## 2026-10-18 最終候補: 計算削減と鎖内ω補正

提出の基準は自作の `22e1dc1` 版であり、公開V29への置き換えではない。
候補のソース・SHA256・上書き属性と比較方向は `research/frozen_phase2_final.json`、
最終確認の採否条件は結果を見る前に作成した `research/protocol_phase2_final.json` に固定した。
公式full64〜127を開発に使用し、128〜255は凍結後の一度だけの最終確認に使う。

### 数式と実装

- **同値な計算削減**: 大きな因子化行列積を幅優先Strassen–Winogradの7乗算・15加減算形で計算する。
  乗算量はL段で概ね `(7/8)^L` 倍になり、加減算・コピーの実費もflopscopeに課金される。
  若い家族の輸送を一括化し、Hermite多項式とペア項もまとめる。FP32の丸め順序は変わる。
  通常の競技形状では4段、深さ16を超える安全検査形状では通常の行列積を使う。
  Strassen利用可の主催者回答はフォーラム投稿18218を参照した。
- **球面入力の動径分離**: バイアスなしReLU網の正の1次斉次性により、
  `E[h(x)] = c_n E[h(√n u)]`、
  `c_n = √2 Γ((n+1)/2) / (√n Γ(n/2))` と分ける。
  球面側の共分散はI、初期4次コアは `G = -6 I/(n+2)`。
  鎖を球面側で近似して最後に動径因子を掛ける。分離自体は恒等式だが、有限次数の鎖の閉包は近似である。
- **(3,1)二項則**: 従来の共分散方向の項に、
  `b2 κ3_i T_iij / v_i` を加える。公開投稿18246のkai_leal_gonzalez氏をコード内でも明記した。
  導出上の係数は1だが、既使用データで走査し `k31_two_term=3.0` を選んだ。
- **鎖内の学習補正**: 各ニューロンの17特徴をFP32にそろえ、MLP `17→64→64→1` でΔωを計算する。
  出力のニューロン平均を引き、ωの平均ではなく形を補正する。層1以降の球面・二項則あり、
  幅1024・深さ16にのみ適用する。重み・特徴正規化をbase64でroot `estimator.py` に埋め込んだ。
  推論はflopscopeだけを使い、外部checkpointファイルを必要としない。
  学習用真値はGaussian入力から球面側へ変換したもの。公式full0〜63と264〜423を学習に使い、
  最終128網は学習に使っていない。実装と特徴定義は `research/ml_lab/` に保持した。

開発64網で球面＋二項則は基準の最終層MSEに対して対の平均比0.871、
学習補正の追加は補正前に対して0.95934、55/64網で改善した。
後者の調整後スコアは `5.47028e-9 → 5.25052e-9`、C/Bは `0.243407 → 0.243711`。
記録は `results/dev64_strassen_sphere_k31.json`、
`results/ml_lab_dev_v2s_omega_0_63.json`。開発集合での結果であり、本番スコアへの換算ではない。
τも補正する候補、出力だけの補正、κ4の(2,1,1)低ランク誕生は、この候補には採用していない。

### 最終確認の実行履歴

最初の8プロセス×4スレッド実行は基準版の120秒wall超過で中断した。
さらにflopscopeの `TimeExhaustedError` がpickle復元できず `BrokenProcessPool` となり、
網別結果も候補別の精度集計も保存されなかった。履歴は
`results/final128_phase2_aborted_attempt.json`。最終集合には既に実行を試みており、
以降「一切触れていない」とは呼ばない。候補のソース・係数の変更や精度を見た選び直しはしていない。

開発集合の基準版4網で4プロセス×8スレッドを確認し、最大wall23.29秒で完走した。
この32スレッド構成へ変更し、最終評価ハーネスに網単位の追記専用JSONL checkpointと、
pickle不能な例外を文字列として保存する処理を追加した。
`--resume` はソース・プロトコル・実行条件が同じcheckpointだけを受け付け、
保存済みの成功・失敗の行を再実行しない。予測の120秒制限と候補の採否条件は緩めていない。
並列時のresidualは競合時間を含むため、静かな1スレッドの安全検査とは分けて記録する。

固定候補の再実行は全384件の記録を保存して終了したが、基準版126/128件、
計算削減版128/128件、統合版128/128件が `TimeExhaustedError` だった。
`results/final128_phase2.json` と同名 `.jsonl` が実行履歴であり、上書きしない。
集計MSE・調整後スコアはnull、全比較のacceptedはfalse。成功した2件だけで改善率を出さない。
今回の最終確認では事前の「失敗0件」を満たせず、候補の本番採用を承認できない。

評価コードには、spawn先がNumPyをモジュール先頭で読み、`_init` のBLASスレッド設定より先に
初期化する不具合があった。開発用ハーネスはその順序ではないため、開発側の4網検査だけでは
この相違を検出できなかった。NumPyのimportを親のmainと集計関数内へ移し、
子では `_init` の後に読み込むよう修正した。提出用 `estimator.py` の変更ではない。
この時点で再評価は止め、プロトコル例外としてユーザーの明示承認を求めた。
rootのファイルは凍結候補のまま保持し、既存の採用済み提出アーカイブは変更していない。

修正後は最終ハーネスをimportする同じspawn経路で開発先頭4網を実行し、
全子プロセスの実BLASスレッド数が8であることを `threadpoolctl` で確認した。
全4網が21.32〜21.66秒で完走した。これはハーネス修正のsmokeであり、
最終128網の再評価や、候補の採用を裏付ける精度評価ではない。

ユーザーが「固定候補の追加評価を許可」を明示選択したため、修正ハーネスで失敗分だけを追加評価する。
元の成功行（基準版のローカルidx43・75）は再利用し、成功した予測をやり直さない。
候補のソース・係数は固定したまま、結果を `results/final128_phase2_corrected.json`、

## 計算削減版: 薄い因子の再利用と資源配分

4次の式を増やさず、古い家族の残差Pとκ3脚Xを密なn列へ展開・射影していた処理を変更した。
出生時の P=M·dd+A·e+ZQᵀ、X=XqR という因子を保持し、
既に求めたfa=UᵀA、fm=UᵀMと、小さいfz=UᵀZ、fxq=UᵀXqを使う。
共有基底を再直交化した際も、密なFP/FX全体ではなく薄い係数だけを回転する。
読み出しの転置側もQ/Rを先に縮約する。初期の入力共分散IはWᵀWへ、
最終層の分散はdiag(WᵀCW)だけへ縮約し、不要な全行列を作らない。

枝刈りなし・エネルギー保持率1では、同じ数式の代数的な計算順序変更である。
FP32の丸め順序は変わるのでbitwise一致ではない。
生成した幅1024・深さ16・seed1の比較は以下。これは本番スコアの比較ではない。

| 同じ保持設定による比較 | 変更前FLOP | 変更後FLOP | 削減 |
|---|---:|---:|---:|
| 方向依存4次モード | 966,105,456,876 | 883,699,001,581 | 8.53% |
| 従来の放射モード | 933,935,166,840 | 831,458,805,625 | 10.97% |

既定、放射4次誕生、補正なし、κ3脚なし、共有なし、基底再構築、深い層、全階数の基底回転、
旧家族を全て除去する遷移を含む20シナリオを `research/compute_audit.py` で実行した。
同値な幅1024の比較では予測の最大差は約3.94e-6以内、3次切り口もFP32許容差内で一致した。
結果は `results/compute_audit.json`。要求階数が幅を超えたときのreshape失敗は、
実効階数を幅以下にし、Gaussian初層の解析平均も確認する回帰テストで防ぐ。

近似を伴う資源管理は次の別ノブとして実装した。採用は実測スコアで決め、速いだけでは有効にしない。

- `family_prune_rel`：家族ごとの対角3次寄与のL1と追加脚の寄与を相対比較し、弱い家族を次の輸送前に除去。
  全テンソルの誤差保証ではないヒューリスティック。0なら評価・間引きを行わない。
  若い家族と共有済み家族の全因子を同時に詰め直す。
- `rank_old_energy`：小さいQRのRの特異値エネルギーで共有階数を配分。
  `rank_old_min`から`rank_old`までに制限し、1ならSVDを行わず固定階数を維持する。

SA・GA・山登りは `results/compute_search_space.json` を使う。
今回の探索は38設定で、SA16手、GA2世代(集団6)、山登り2周を実行した。
32 CPUスレッド(8プロセス×4)でW&Bへ記録し、評価・イベントごとにcheckpointを保存した。
共有基底を256から64へ削る設定や、エネルギー保持率0.995以下のSVD圧縮は、
fast8では計算量の削減以上にMSEが増えた。小さい補助階数4/4が有望で、

## 方向依存κ4の再生とヒューリスティック探索

前の標準化トレース閉包とは別に、閉包内でrawな4次コアの対角を厳密に運び、
非対角は利用済みの共分散の方向で再生する方式を `candidates/k3_factored.py` に追加した。
未使用の最終4個でも採用条件を満たしたため、`directional_k4=True` を既定にした。

コアの規約は κ4=(1/6)Sym6(G⊗I)、G=diag(g)+λC_off。
4次テンソル全体の厳密伝搬ではなく、この調和成分を保持する近似である。
ReLU後の分散で割る射影は行わず、rawな K4 と K22 の行和 H を用いて
g=6H/(n+4)-3ΣH/((n+2)(n+4)) とする。
線形層では t_g=(W²)ᵀg、t_v=diag(WᵀCW)-(W²)ᵀdiag(C) から
λ=s mean(t_g)/(mean(var)-s mean(t_v))、diag(G_pre)=t_g+λt_v と求める。
非正の分母は候補不適合として拒否し、修復や例外の隠蔽はしない。

4次→3次の誕生は、既存の家族の2つの行列積へ係数を折り込む。
新たな家族ごとの密行列積は増やさず、追加は要素積・薄い積と層ごとのO(n²)処理。
`regen_audit.py` で Sym6 の1/6、(3,1)の1/2、誕生脚の metric/var、
若い家族・共有基底での密テンソルとの一致、raw対角射影・輸送を独立に数値検証した。
幅128でテンソル式・射影の65検査を通過したが、この時点では周辺分布の正値性を含んでいなかった。
全階数の共有基底と若い家族だけの実行も、FP32誤差内で平均・D3・D21が一致した。
無効時に旧版と同じ保持設定を明示した比較では、同じBLASスレッド数で予測がbitwise一致し、FLOPも一致した。
現行既定の `age_old` は7なので、旧版の再現には `False` だけでなく `results/directional_protocol.json` の旧設定が必要。

開発用 seed26051511 の初期設定(未探索、参照雑音差し引き)では以下。
このネットワークは以前の診断で使用済みであり、最終確認ではない。

| 方式 | 最終MSE | C/B | 調整後 |
|---|---:|---:|---:|
| 従来 | 3.85e-8 | 0.4247 | 1.63e-8 |
| 方向依存再生・初期値 | 3.61e-8 | 0.4274 | 1.54e-8 |

対角保持・共分散方向への再生の方針と正規化の確認には、
[504aldoの公開MIT実装](https://github.com/504aldo/whest-p2-cumulant-k3)
の `docs/derivation_code_map.md` §2.4/2.6 とARCの `factor_k3.py` を参照した。
公開実装の係数表は転用せず、rawモーメントの式と家族への折り込みを実装し直して検算した。

探索は `search_directional_k4.py` のSA・GA・山登りで行う。層方向4節点の係数、
4次→3次の寄与、(3,1)使用量、適用層、古い家族の年齢・階数を探索対象にする。

### 正値周辺密度での修正

方向依存κ4の行列コアと3次家族の表現は維持し、単変量のReLUモーメントだけを
p(q)∝φ(q)[1+u(q)+u(q)²/2] へ置き換えた。
1+u+u²/2=(1+(1+u)²)/2>0 なので、符号付き密度の打切りではない。
確率密度を正規化し、さらに平均0・分散1へ厳密に中心化・標準化してからReLUを積分する。

```
u = (τ/6−τω/4) H3 + (ω/24−τ²/8−ω²/16) H4 − τω H5/12 − ω² H6/72
```

Hkは確率論的Hermite多項式。標準化後、τとωの全次数2までの展開は
H3:τ/6、H4:ω/24、H5:0、H6:τ²/72、H7:τω/144、H8:ω²/1152。
従来のτ²/72項を保ち、混合項とω²項も整合させる。H5/H6は新たな5次/6次キュムラントの状態ではない。
大きな非Gaussian性までκ3/κ4を厳密に一致させるモデルではなく、弱非Gaussian域の展開整合と正値性を両立する閉包である。
積分はGaussianの切断モーメントとHermite積公式で解析的に行い、追加処理はベクトルのみ。

実行中のraw分散は丸め誤差の許容値を超えて負なら明示的に拒否する。
ゼロへの修復で不適合を隠さず、線形層の分散についてもfloor前の値を監査する。
さらに、flopscopeのGaussian CDFは `(1+erf)/2` なので深い負の裾で桁落ちする。
幅1024の実例(α≈−8.79)でこの問題を検出し、負の裾ではMills比のLaplace連分数を用いて修正した。
これは小さな負の出力を切り捨てる処理ではない。

`results/regen_positive_n128.json` は143検査に合格。
正値密度の独立な一次元求積、上の2次係数の有理数検算、実ネットワークのrawコア輸送と
floor前の分散を含み、以前失敗した幅128でも負のraw分散はゼロ件。
裾の求積はGaussianの指数因子を外へ出し、微小モーメントを絶対許容誤差で素通りさせない。

```bash
uv run --with scipy python research/regen_audit.py \
  --network /kaggle/ext/closure/network_n128_s26051503.npz \
  --kwargs '{"directional_k4":true,"regen_p0":1.2,"regen_p1":1.2,"regen_p2":1.2,"regen_p3":1.6,"age_old":7,"k3leg_rank":32}'
```

## 数式の要点

- 事前活性化 `z` の状態 `(m, S, T)`: 平均・共分散・3次キュムラント。κ4 は放射部分だけ(κ̃4_iiii = ω、κ̃4_iijj = ω/3)。
- ReLU 後の共分散は Hermite 展開の接続図の和(Mehler 項 + τ の 1 次 + κ4 放射の 1 次)。
- T は家族の和で持つ: `T = Σ_q c2_q Sym(A A M) + Σ_q Sym(M M PΔ)`、`PΔ = A diag(e) + M diag(dd) + Z Qᵀ`。
  ReLU が読むのは `D3 = T_aaa` と `D21 = T_aab` だけ(家族全体で n³ の行列積 2 回)。
  輸送は `X ← Wᵀ diag(Φ(α)) X`(X = A, M, Z)。家族は横並びの行列で持ち、家族数によらず演算回数が一定。
- ω の層平均は表 `ω_ℓ = G[ℓ]/n`(MC 実測、参照実装の解析値と 2〜15% で一致)。

## 測って分かったこと(要点)

- 周辺の非ガウス性(Edgeworth)は誤差の約 5%。残りは μ_z, σ_z の伝播誤差で、ニューロン間の
  交差キュムラントが主因(独立和の近似は κ4 を 60 倍過小評価)。
- 密版の項のうち効くのは `rho`, `tau1`, `pairtau`, `meantau`。`tau1e`, `txxx` は不要、`txxy` は約 5%。
- 古い源を捨てる(window)のは旧版では得だったが、家族版では窓 16(全部持つ)が最良。窓 10 では最終層 MSE が 2 倍以上悪い。
- 学習補正: 9 特徴の ridge(0.816)・GBM(0.83〜0.85)は 1 パラメータの縮小(0.825)を超えない。

## 未実装・既知の制約

- 深さが 16 を超える場合の ω 表は外挿。FLOP ガードで予算内には収まる(深さ 24 で 0.78B、32 で 0.69B)。
- Strassen 型の分割は、公平性の扱いが不明なので使っていない。
- residual 時間は 0.22 s 前後で、上限 0.4 s までの余裕は約 1.8 倍。評価機が遅い場合の余裕は小さい。
- 家族版の定数は ω の表だけ(倍率 1、縮小係数 0)。縮小係数の解析的最適値は -1.4e-6 でほぼ 0。
